# Application Slip PDF (Phase 2.6)

**Date**: 2026-08-08 · **Status**: Approved design (Wave 2) · **Source**: roadmap §2.6

## 1. Problem
The HOW TO APPLY boilerplate promises an application slip ("download the application slip generated by the system with unique application number") — nothing generates one.

## 2. Goal
A downloadable A4 receipt PDF per application, available to candidates after successful application.

## 3. Contents (new `recruitment/slip_pdf.py`)
- OrgProfile letterhead (name_en + tagline + address) — same pattern as advt_pdf.
- "APPLICATION SLIP" title + `Application ID` (application_id), `Advertisement No`, `Post` (name + code), `Candidate Name`, `Date of Application` (applied_at), `Application Status`.
- **Fee payment status** line: since no payment gateway exists, render "Fee status: Exempted (SC/ST/PwBD/ESM/Female)" when `profile.category` in the exempt set and the post has a category-appropriate exemption, else "Fee status: To be paid — Rs 500/- (online)". Computed from `post.category_breakup` + `candidate.profile.category` (deterministic, documented).
- **Document checklist status**: rows per uploaded `Document` (doc_type + uploaded yes/no + extracted doc_type when parse_document_task classified it).
- Footer: "No document is required to be sent by post." + Page X of Y.

## 4. View
`portal/views.py`: `application_slip(request, application_id)` — `@require_portal_user`, owner-check (application.candidate.portal_user == request.user), returns `HttpResponse(content_type="application/pdf")` with `Content-Disposition: attachment; filename="slip-<application_id>.pdf"`. URL `portal/applications/<id>/slip/` (name `portal_application_slip`). Button on `portal/application_detail.html` ("Download Application Slip").

## 5. Testing (`portal/test_slip.py` or append to portal tests)
- `test_slip_pdf_download`: applied application → GET slip URL → 200, content-type application/pdf, bytes start `%PDF`.
- `test_slip_contains_application_data`: extract text (doc_intel) → contains application_id, candidate name, post name, the no-post footer.
- `test_slip_owner_only`: another portal user's request → 403/redirect.
