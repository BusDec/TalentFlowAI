# Offer Letter PDF + Acceptance Flow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use `- [ ]` syntax.

**Goal:** Formal offer PDF (staff download) + candidate acceptance flow (offered → joined, employee number auto-gen). Spec: `docs/superpowers/specs/2026-08-08-offer-pdf-design.md`.

## Global Constraints
- Staff `offer_letter` view streams PDF bytes (keep `generate_offer_text` — still used by tests; don't delete).
- Acceptance: checkbox required; status → `joined`; `employee_number = f"{advt.post.advertisement.advt_number[:6]}-{post.post_code}-{seq:04d}"` with seq = count of joined applications for that post + 1 (not unique-constrained; documented).
- Status change audited via existing `Application.save(audit_actor=...)`; the view additionally calls `log_audit(None, application, "status", old, "joined", reason="candidate accepted offer")` only if the save didn't cover the reason (save audits without reason — add the reason-carrying audit call in the view).
- Owner-check the accept route. Python: `.venv/Scripts/python.exe`; pytest `--reuse-db` + 30s retry (max 3); no migrate/full suite. Commits: `Phase 2: OfferPDF — offer letter PDF` and `Phase 2: OfferPDF — acceptance flow with employee number`.

def test_accept_moves_to_joined(api_client, candidate_portal_user, application):
