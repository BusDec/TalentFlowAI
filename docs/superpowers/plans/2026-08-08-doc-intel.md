# Document Intelligence Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Text-first extraction, document-type classification, per-type structured extraction with per-field confidence and format validation, cross-doc consistency, and a `parse_document_task` wired into the portal upload path.

**Architecture:** New `agents/doc_intel.py` (pure functions: extract_text → classify_document → per-type extractors → extract_document → check_consistency); `resume_parser.extract_text` delegates to the text-first path; new Celery task + eager wiring in the portal apply flow.

**Tech Stack:** Django 6.0, PyMuPDF (fitz) optional, pytesseract optional, pytest (57 existing).

## Global Constraints

- LLM-first → deterministic fallback must survive: every extraction works with NO API key (`is_configured()` gate, existing pattern).
- No hard dependencies: fitz / pytesseract / cv2 all optional imports; each step degrades to "" or heuristic.
- `parse_resume(path)` signature/return unchanged (tasks + tests depend on it).
- Document.doc_type is a plain CharField — classifier may set it; never clobber user-chosen values when the classifier returns `unknown`/`resume` for non-resume uploads.
- Python: `.venv/Scripts/python.exe`; targeted pytest; commit format `Phase 2: DocIntel — <brief>`.
